# Story 8.0: Extract structured fields from a PDF or JPEG notice

## Status
Ready for development

## Epic
Epic 8: Notice Comparison Tool

## User Story
As a reviewer, I want the system to extract structured notice fields from an uploaded PDF or JPEG using an LLM so that I can begin the comparison workflow without manually pasting or uploading JSON.

## Goal
Provide a reliable extraction step that converts uploaded notice documents into a structured payload matching the schema expected by the diff engine.

## Scope
In scope:
- Accept uploaded PDF or JPEG files through the Streamlit UI
- Use PyMuPDF (fitz) to extract embedded text from PDFs
- Read direct AcroForm widget values from fillable PDFs using PyMuPDF's form-field API, treating them as the most reliable field values
- Also extract regular page text for surrounding template or prose content from those PDFs
- For scanned PDF pages or image-based pages, render the page to an image and run EasyOCR on it
- Run EasyOCR directly on JPEG images
- Merge form field values, page text, and OCR output into the final raw text used for both field parsing and paragraph-level comparison
- Apply regex and keyword-based parsing rules to recover notice_id, recipient, amount_due, due_date, and related fields from extracted text
- Surface actionable errors for failed extraction, OCR failures, and insufficient parsed content

Out of scope:
- General-purpose document OCR for unrelated use cases
- Automatic retries with complex backoff logic beyond basic graceful error handling
- Legal interpretation of extracted content

## Acceptance Criteria
- The system accepts an uploaded PDF or JPEG notice as input.
- The system extracts a structured dict matching the schema already expected by the diff engine.
- The system handles multi-page PDFs and returns the combined structured result.
- For fillable PDF forms, the system first reads AcroForm widget values directly via PyMuPDF and uses those values as the most trustworthy source.
- The system also extracts regular page text via fitz and runs OCR where needed, rather than treating embedded text and OCR as mutually exclusive.
- The final raw text used for parsing and document diffing combines form values, page text, and OCR content, with form values distinguished from surrounding template text.
- The system returns a clear error when extraction fails or when the document cannot be interpreted reliably.
- The system makes extraction automatic so the app’s input model is “upload PDF/JPEG, extraction happens automatically” rather than “paste/upload JSON.”

## Implementation Notes
- Implement the extraction workflow in src/extractor.py.
- Use PyMuPDF (fitz) to read PDF text directly and inspect AcroForm widgets for fillable form values.
- For scanned pages, image-based pages, or pages where embedded text is sparse, render the page to an image and run EasyOCR on it; do not skip OCR solely because a few characters or a header are present.
- For JPEG files, run EasyOCR directly on the image bytes.
- Merge all extracted sources into a single raw text view used by both the structured parser and the paragraph-level diff: direct form values, surrounding page text, and OCR text.
- Distinguish direct field-value sources from template/prose text so reviewers can see which values came from form widgets versus body text.
- Apply regex and keyword-based parsing rules to recover fields such as notice_id, recipient, amount_due, and due_date.
- Validate the parsed payload before passing it into compare_notices().
- Raise or return structured errors for unreadable files, OCR failures, and missing required fields.

## Suggested Functions
- extract_text_from_pdf(file_bytes)
- extract_text_from_image(file_bytes)
- parse_notice_fields(text)
- extract_notice_fields(file_bytes, file_type)
- validate_extraction_payload(payload)
- raise_extraction_error(message, reason=None)

## Definition of Done
- The extraction module can be called from the Streamlit app for uploaded PDF and JPEG files.
- The module validates JSON output and rejects malformed or low-confidence results.
- The UI displays clear error messaging when extraction fails.
- The architecture and PRD both reference the extraction workflow.
