# Story 8.3: Full-text paragraph-level diff for prose and clause-based documents

## Status
Ready for development

## Epic
Epic 8: Notice Comparison Tool

## User Story
As a reviewer, I want the system to compare the full text of two documents paragraph by paragraph so that I can identify changes in prose, clauses, and narrative language even when the documents do not fit a rigid field schema.

## Goal
Provide a second, complementary comparison path alongside structured extraction so the tool can review any document type, not just notices with recognizable label/value fields.

## Scope
In scope:
- Accept two uploaded documents of any type, including notices, leases, and other text-heavy content
- Extract raw text from both documents
- Split the text into paragraph units using double newlines when available, with single-newline fallback for noisier documents
- Compare paragraph lists using Python difflib
- Label paragraphs as unchanged, changed, added, or removed
- Show the full-text diff alongside the structured field comparison in the same review workflow

Out of scope:
- Full legal interpretation or semantic summarization
- AI-driven clause rewriting
- Perfect paragraph segmentation for low-quality OCR output
- Replacing the field extraction workflow

## Acceptance Criteria
- The system accepts two document inputs and extracts raw text from each.
- The system splits the raw text into paragraph-like chunks according to clear paragraph separators when available, and uses a fallback split on single newlines when the document structure is not clear.
- The system compares the paragraph lists using Python difflib and identifies unchanged, changed, added, and removed paragraphs.
- The system shows before/after values for changed paragraphs, and it preserves reading order for easy review.
- The system continues to show structured field extraction results when recognizable label/value pairs are present.
- The system can compare documents that include both machine-readable fields and narrative prose without forcing everything into a fixed schema.
- The system handles OCR-noisy input gracefully; paragraph boundaries may be imperfect, but the comparison remains useful.
- The full-text diff is available in the same UI as the structured-field comparison and clarifies when the document is materially different beyond a field mapping.

## Implementation Notes
- Use a helper function such as compare_paragraphs(left_text, right_text) in a dedicated text-diff module.
- Split paragraphs with a regex or line-based normalization strategy that prioritizes double line breaks, then falls back to single-line splitting.
- Clean the paragraphs by stripping extra whitespace but preserving the order of the content.
- Use difflib.SequenceMatcher or difflib.unified_diff to identify paragraph-level changes.
- Return a result object with entries such as:
  - unchanged
  - changed with before/after text
  - added with the new text
  - removed with the deleted text
- Keep the paragraph diff independent from the structured field parser so the two outputs can be reviewed side by side.
- Note that OCR or scanned-source documents may produce noisier paragraph boundaries; the feature should degrade gracefully rather than crashing.

## Suggested Functions
- split_into_paragraphs(text: str) -> list[str]
- compare_paragraphs(left_text: str, right_text: str) -> dict
- normalize_paragraph_text(text: str) -> str
- classify_paragraph_change(before: str, after: str) -> str

## Definition of Done
- The paragraph diff helper works with sample text containing paragraphs, changed clauses, and added/removed language.
- The output is easy to consume in the UI and clearly identifies paragraph-level changes.
- The feature is documented in the architecture and linked to the PRD.
- The structured field comparison and full-text diff can both be reviewed without replacing one another.
