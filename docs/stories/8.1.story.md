# Story 8.1: Field-by-field diff between two extraction results

## Status
Ready for development

## Epic
Epic 8: Notice Comparison Tool

## User Story
As a reviewer, I want the system to compare two extraction results field by field so that I can quickly identify what changed and assess whether the difference is material.

## Goal
Provide a reliable, explainable difference report that highlights additions, removals, and modifications between two structured notice extraction results built from arbitrary field labels.

## Scope
In scope:
- Accept two structured extraction results as input
- Build the comparison against the union of normalized labels discovered across both notices
- Detect added, removed, changed, and missing values
- Normalize common formatting differences where appropriate
- Produce a structured diff result with a recommended classification

Out of scope:
- Legal interpretation of the change
- Full natural-language semantic understanding
- Persistence of history beyond the current review session

## Acceptance Criteria
- The system accepts two JSON-like extraction results as input.
- The system compares the union of all normalized labels found across both notices rather than a fixed whitelist of known fields.
- The system reports added, removed, changed, and missing values, and any label present in only one notice is flagged as missing or extra instead of being silently skipped.
- The system normalizes labels before comparison by lowercasing, trimming whitespace, collapsing repeated spaces, and standardizing underscores/spaces.
- The system can compare nested objects and lists without crashing.
- The system handles missing values and partial data gracefully.
- The system returns a structured diff result that includes path, change type, before value, after value, and a summary.
- The system produces a recommended classification of same, materially different, or needs review.
- The system is testable without requiring the Streamlit UI.

## Implementation Notes
- Implement the comparison logic in src/diff_engine.py.
- Keep the module free of Streamlit-specific dependencies.
- Use a recursive comparison approach for dicts and lists.
- Normalize labels and values such as whitespace, case, and common date formats when appropriate.
- Derive the comparison set from the union of labels in both notices instead of comparing only shared fields.
- Treat field-level changes, including missing values, as evidence for a higher-level classification.
- Replace the fixed regex-per-field approach from field_rules.py with a generic line-parsing function that can detect arbitrary label/value pairs.

## Suggested Functions
- normalize_label(label)
- normalize_value(value)
- parse_label_value_line(line)
- collect_label_value_pairs(text)
- compare_values(left, right, path="")
- compare_dicts(left, right, path="")
- compare_lists(left, right, path="")
- build_diff_result(left, right)
- classify_diff(diff_result)

## Definition of Done
- Unit tests cover added, removed, changed, nested, and missing-field cases.
- The diff engine returns a structured result that the Streamlit UI can consume.
- The implementation is documented in the architecture and linked to the PRD.
