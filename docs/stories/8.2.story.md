# Story 8.2: Side-by-side human-readable view

## Status
Ready for development

## Epic
Epic 8: Notice Comparison Tool

## User Story
As a reviewer, I want a side-by-side view of the two extraction results so that I can inspect differences in context and make a confident decision.

## Goal
Render a clear, human-readable comparison experience that shows both notices side by side and highlights differences in a way that is easy to review.

## Scope
In scope:
- Render two notice views in parallel
- Highlight added, removed, and changed fields visually
- Show missing fields clearly
- Support a confirm workflow for match / mismatch / needs review

Out of scope:
- Full document editing capabilities
- Advanced visualization beyond the comparison view
- Backend persistence of review decisions beyond the session state

## Acceptance Criteria
- The UI displays the two notices in a side-by-side layout.
- Added, removed, and changed fields are visibly highlighted with consistent visual treatment.
- The reviewer can distinguish unchanged values from modified values without ambiguity.
- Missing values are clearly indicated in the comparison view.
- The reviewer can select a confirm action: Confirm Match, Confirm Mismatch, or Need More Review.
- The selected review decision is stored along with the comparison evidence.

## Implementation Notes
- Build the UI in app.py using Streamlit.
- Use Streamlit session state to hold notice A, notice B, the comparison result, and the review decision.
- Use clear visual indicators for difference types:
  - added: green highlight
  - removed: red highlight
  - changed: amber or blue highlight
- Ensure the interface remains readable and accessible with keyboard navigation and clear labels.

## Suggested UI Components
- Header with comparison status badge
- Two-column comparison pane
- Difference chips or labels for each field row
- Review action buttons at the top or bottom of the page

## Definition of Done
- The comparison view renders for sample notice data.
- Review actions work end to end in the current session.
- The UI is understandable to a non-technical reviewer and meets the accessibility expectations in the UX spec.
